## Global Constraints

- Nguồn câu hỏi duy nhất là 500 câu trong `data/questions.json` (sinh từ `Question-Doc/`). **Không tạo thêm câu hỏi, không sửa đáp án gốc, không sửa `Question-Doc/`, `data/questions.json`, `data/meta/`, `data/sets.json`, `data/service-registry.json`.** Nếu nghi đáp án sai, chỉ gắn `review: { reason }`.
- Schema mỗi câu: `{ id, stemVi, promptVi, options: [{ key /* nhãn gốc */, textVi, reason }], explanationVi, keyHint, review?: { reason } }`.
- File `data/vi/qSSS-EEE.json` là mảng JSON của đúng 25 câu, sắp theo id, soạn theo lô 25 câu lần lượt từ Q1 đến Q500 (`q001-025.json`, `q026-050.json`, …, `q476-500.json`).
- Tên service và thuật ngữ AWS giữ nguyên tiếng Anh; các cụm từ khóa (LEAST operational overhead, MOST cost-effective…) được dịch kèm bản gốc.
- `reason`, `explanationVi`, `keyHint`, `review.reason` **không được dùng chữ cái A/B/C…** để chỉ lựa chọn (thứ tự lựa chọn bị xáo). Phải nói theo nội dung.
- Mỗi lựa chọn đều có `reason`: lựa chọn đúng nói vì sao đúng, lựa chọn sai nói vì sao sai.
- Hai câu trùng nguyên văn (cặp trong `sets.json` `duplicates`: 159/218, 246/253, 278/336, 393/476) có bản dịch giống hệt nhau, chỉ khác `id`.
- Chạy lệnh trong Git Bash; khi in tiếng Việt bằng Python, dùng `PYTHONIOENCODING=utf-8`.
- Kết thúc mỗi lô: `npm run validate` phải `0 lỗi`.

## Review Focus

1. Chữ cái chỉ lựa chọn viết theo dạng khác bốn từ khóa cũ ("chọn B", "A và C", "(D)", "câu A", "Answer B") → phải bị bắt. Test: Task 1 `hasLetterRef` các ca dương tính.
2. Văn bản hợp lệ trông giống chữ cái chỉ lựa chọn ("bản ghi A", "EC2 C5", "Standard-IA", "AWS và Azure", "(Chọn hai.)") → không được báo lỗi, nếu không người soạn sẽ phải viết vòng. Test: Task 1 `hasLetterRef` các ca âm tính.
3. Câu có đề bài trống (Q467 chỉ có câu hỏi) → `stemVi: ""` phải hợp lệ, còn câu có đề mà thiếu `stemVi` phải báo lỗi. Test: Task 1.
4. Câu nhiều đáp án (67 câu "Choose two/three") → mọi lựa chọn phải có `reason` không rỗng. Test: Task 1 "thiếu nội dung"; nội dung đúng/sai do reviewer của từng task đối chiếu.
5. Hai câu trùng soạn ở hai lô khác nhau → bản dịch lệch nhau phải báo lỗi. Test: Task 1 "câu trùng".

```ts
import type { Question, QuestionVi } from '../../src/data/types';

export interface ViReport {
  errors: string[];
  warnings: string[];
}

const OPT = '[A-E]';
const START = '(?<![\\p{L}\\p{N}])';
const END = '(?![\\p{L}\\p{N}])';

// Chữ cái in hoa A–E đứng riêng, đi sau từ chỉ lựa chọn, đi thành cặp, nằm trong ngoặc, hoặc đứng đầu dòng.
const LETTER_PATTERNS: RegExp[] = [
  new RegExp(`(?:[Đđ]áp án|[Pp]hương án|[Ll]ựa chọn|[Cc]họn|[Cc]âu|[Oo]ptions?|[Cc]hoices?|[Aa]nswers?)\\s+${OPT}${END}`, 'u'),
  new RegExp(`${START}${OPT}\\s*(?:,|và|hoặc|/|&|or|and)\\s*${OPT}${END}`, 'u'),
  new RegExp(`\\(\\s*${OPT}\\s*\\)`, 'u'),
  new RegExp(`(?:^|\\n)\\s*${OPT}[.):]\\s`, 'u'),
];

export function hasLetterRef(text: string): boolean {
  return LETTER_PATTERNS.some((re) => re.test(text));
}

function blank(s: string | undefined): boolean {
  return !s || s.trim() === '';
}

export function validateVi(
  questions: Question[],
  vis: QuestionVi[],
  duplicates: [number, number][] = [],
): ViReport {
  const errors: string[] = [];
  const warnings: string[] = [];
  const byId = new Map(questions.map((q) => [q.id, q]));
  const viById = new Map<number, QuestionVi>();

  for (const v of vis) {
    if (viById.has(v.id)) errors.push(`vi: câu ${v.id} bị trùng`);
    viById.set(v.id, v);
    const q = byId.get(v.id);
    if (!q) {
      errors.push(`vi: câu ${v.id} không tồn tại`);
      continue;
    }
    const origKeys = q.options.map((o) => o.key).sort().join(',');
    const viKeys = v.options.map((o) => o.key).sort().join(',');
    if (origKeys !== viKeys) errors.push(`vi: câu ${v.id} có key lựa chọn không khớp bản gốc`);

    const missing: string[] = [];
    if (q.stem.trim() !== '' && blank(v.stemVi)) missing.push('stemVi');
    if (blank(v.promptVi)) missing.push('promptVi');
    if (blank(v.explanationVi)) missing.push('explanationVi');
    if (blank(v.keyHint)) missing.push('keyHint');
    for (const o of v.options) {
      if (blank(o.textVi)) missing.push(`textVi của ${o.key}`);
      if (blank(o.reason)) missing.push(`reason của ${o.key}`);
    }
    if (missing.length > 0) errors.push(`vi: câu ${v.id} thiếu nội dung: ${missing.join(', ')}`);

    if (v.review && blank(v.review.reason)) errors.push(`vi: câu ${v.id} có review nhưng thiếu lý do`);
    const texts = [v.explanationVi, v.keyHint, v.review?.reason, ...v.options.map((o) => o.reason)];
    if (texts.some((t) => hasLetterRef(t ?? '')))
      errors.push(`vi: câu ${v.id} nhắc lựa chọn bằng chữ cái (không được vì đáp án bị xáo)`);
    if (v.review && !blank(v.review.reason)) warnings.push(`vi: câu ${v.id} được gắn cờ review: ${v.review.reason}`);
  }

  for (const [a, b] of duplicates) {
    const va = viById.get(a);
    const vb = viById.get(b);
    if (va && vb && JSON.stringify({ ...va, id: 0 }) !== JSON.stringify({ ...vb, id: 0 }))
      errors.push(`vi: câu ${a} và ${b} trùng nhau nhưng bản dịch khác nhau`);
  }

  const missingVi = questions.filter((q) => !viById.has(q.id)).length;
  if (missingVi > 0) warnings.push(`${missingVi} câu chưa có bản dịch tiếng Việt`);
  return { errors, warnings };
}
```

```ts
import type { Question, QuestionMeta } from '../../src/data/types';

export const BATCH_SIZE = 25;

const pad = (n: number) => String(n).padStart(3, '0');

export function batchRange(start: number, size = BATCH_SIZE): { start: number; end: number; file: string } {
  const end = start + size - 1;
  return { start, end, file: `q${pad(start)}-${pad(end)}.json` };
}

export function twinSource(id: number, duplicates: [number, number][]): number | undefined {
  for (const [a, b] of duplicates) {
    if (b === id && a < b) return a;
    if (a === id && b < a) return b;
  }
  return undefined;
}

export function formatBatch(
  questions: Question[],
  metas: QuestionMeta[],
  duplicates: [number, number][],
  start: number,
  end: number,
): string {
  const metaById = new Map(metas.map((m) => [m.id, m]));
  return questions
    .filter((q) => q.id >= start && q.id <= end)
    .sort((a, b) => a.id - b.id)
    .map((q) => {
      const m = metaById.get(q.id);
      const lines = [
        `=== Câu ${q.id} · domain ${m?.domain ?? '?'} · độ khó ${m?.difficulty ?? '?'} · chọn ${q.choose} · đáp án: ${q.answer.join(', ')} ===`,
      ];
      if (m) lines.push(`services: ${m.services.join(', ')}`);
      const twin = twinSource(q.id, duplicates);
      if (twin !== undefined) lines.push(`TRÙNG với câu ${twin}: chép nguyên bản dịch của câu ${twin}, chỉ đổi id.`);
      lines.push('STEM:', q.stem.trim() === '' ? '(trống)' : q.stem, `PROMPT: ${q.prompt}`);
      for (const o of q.options) lines.push(`${o.key}. ${o.text}`);
      lines.push(`GIẢI THÍCH GỐC: ${q.explanationOrig}`);
      return lines.join('\n');
    })
    .join('\n\n');
}
```

````markdown
# Hướng dẫn soạn nội dung tiếng Việt (`data/vi`)

Người học đọc phần này **sau khi** làm câu hỏi bằng tiếng Anh. Mục tiêu: hiểu đề nói gì, vì sao đáp án đúng, và vì sao từng lựa chọn còn lại sai, để lần sau tự nhận ra.

## Quy tắc bắt buộc

1. **Không sửa đáp án, không thêm câu.** Nhãn `Đúng`/`Sai` trên web lấy từ đáp án gốc. Nếu chắc chắn đáp án gốc sai hoặc đã lỗi thời theo tài liệu AWS hiện hành, vẫn viết `reason` theo đáp án gốc, rồi thêm `"review": { "reason": "..." }` nêu lựa chọn (theo nội dung) có vẻ đúng hơn và vì sao. Chỉ gắn cờ khi có căn cứ rõ, không gắn vì "có thể tranh cãi".
2. **Không dùng chữ cái để chỉ lựa chọn** trong `reason`, `explanationVi`, `keyHint`, `review.reason`: thứ tự lựa chọn bị xáo mỗi lượt thi. Không viết "đáp án A", "phương án B", "chọn C", "câu D", "A và B", "(E)". Nói theo nội dung: "cách dùng Athena", "phương án tự viết Lambda", "lựa chọn dùng S3 Glacier Deep Archive". `npm run validate` sẽ báo lỗi nếu lọt.
3. **Mỗi lựa chọn đều có `reason`** (1–3 câu):
   - Lựa chọn đúng: nói nó thỏa **từng** yêu cầu trong đề ra sao.
   - Lựa chọn sai: nêu lý do cụ thể — vi phạm yêu cầu nào, tốn công vận hành/chi phí hơn ở chỗ nào, hay không làm được về kỹ thuật. Không viết chung chung kiểu "không phù hợp".
4. **Thuật ngữ:** tên service và thuật ngữ AWS giữ nguyên tiếng Anh (S3 bucket, VPC endpoint, IAM role, security group, Multi-AZ, read replica, Auto Scaling group…). Cụm từ khóa của đề dịch kèm bản gốc trong ngoặc:

   | Tiếng Anh | Dịch |
   |---|---|
   | LEAST operational overhead | ít công vận hành nhất (LEAST operational overhead) |
   | MOST cost-effective / MOST cost-efficient | tiết kiệm chi phí nhất (MOST cost-effective) |
   | MOST operationally efficient | hiệu quả vận hành nhất (MOST operationally efficient) |
   | highly available | có tính sẵn sàng cao (highly available) |
   | fault tolerant | chịu lỗi (fault tolerant) |
   | durable / durability | độ bền dữ liệu (durability) |
   | scalable | có khả năng mở rộng (scalable) |
   | decouple | tách rời (decouple) |
   | with the LEAST amount of changes / minimal changes | ít thay đổi nhất |
   | (Choose two.) / (Choose three.) | (Chọn hai.) / (Chọn ba.) |

   "solutions architect", "company", tên riêng, số liệu và đơn vị giữ nguyên nghĩa và giá trị.

## Từng trường

- `id`: số câu.
- `stemVi`: dịch đầy đủ đoạn đề, giữ ngắt đoạn bằng `\n\n` như bản gốc. Đề gốc trống (chỉ có câu hỏi) thì để `""`.
- `promptVi`: dịch câu hỏi in đậm, kể cả phần "(Chọn hai.)".
- `options`: đủ mọi lựa chọn, `key` là **nhãn gốc** (A, B, C… đúng như bản gốc), sắp theo `key`. `textVi` dịch sát nghĩa lựa chọn. Tên cũ của service (ví dụ Amazon Elasticsearch Service) giữ như bản gốc; có thể nhắc tên mới trong `reason`.
- `explanationVi`: 2–5 câu: yêu cầu then chốt của đề → vì sao (các) lựa chọn đúng thắng → bẫy thường gặp. `GIẢI THÍCH GỐC` chỉ là ghi chú ngắn, thường dùng chữ cái: dùng làm gợi ý, viết lại, sửa và bổ sung khi cần.
- `keyHint`: 1 câu: trích (các) từ khóa tiếng Anh trong đề trong ngoặc kép → service/mẫu kiến trúc cần nghĩ tới.
````
